# Contributing

Bug reports and changes are welcome. [README.md](README.md) says how to build, check and measure;
[docs/adding-a-core.md](docs/adding-a-core.md) walks through adding a core or a system, and ends
with what cores have taught us. Run `make check` (formatting, clippy with warnings denied, every
test, and the desktop and stock builds) before sending a change.

## Signing off (DCO)

Every commit carries a `Signed-off-by:` line with your real name and email, saying you wrote it
or have the right to submit it under this licence: the
[Developer Certificate of Origin](https://developercertificate.org/). `git commit -s` adds it;
CI checks every commit of a pull request for one.

## Licence

nibcase is MIT ([LICENSE](LICENSE)). By contributing you agree that your contribution is licensed
under the same terms.

A new dependency must be under a licence MIT code can use and ship (MIT, Apache-2.0, BSD, Zlib,
ISC, Unicode and the like; nothing copyleft built into nibcase, nothing non-free). After changing
`Cargo.lock`, regenerate the notices:

```bash
python3 tools/third_party.py > THIRD-PARTY.md
```

## Clean room

nibcase hosts cores; it never contains one. It is written from `libretro.h` and public
documentation alone: don't read or copy another frontend's or an emulator's implementation, and
record every source you used in [docs/provenance.md](docs/provenance.md). Cores are run as black
boxes; their licence and build files may be read.

No ROMs, BIOS files, game artwork or core binaries in the repository, test fixtures included:
tests use the C test core (`crates/testcore`) and original test programs generated by
`tools/*.py`.

## Working against a local nibkit

nibkit comes from its repository at the tag `Cargo.toml` names. To build against a checkout of
your own, add a `[patch]` to `.cargo/config.toml` (gitignored):

```toml
[patch."https://github.com/abradburne/nibkit"]
nibkit = { path = "../nibkit" }
```
